# @core-js/polyfill-provider

The shared core behind `@core-js/babel-plugin` and `@core-js/unplugin`: it detects what the source uses, resolves the types of the receivers it finds, decides what has to be injected, and hands the result to whichever emitter is rendering.

## Target environment

Build-time only, ESM. Node `^22.18.0 || >=24.11.0`.

## Core and bindings

The two plugins are one transpiler with two faces: the same input under the same options produces one semantic output on either host, and an output divergence is legal only as formatting-class or environmental (taxonomy below) - anything else is a defect. Both legs render ASTs, so the render is semantics too and also lives once. The organizing rule: **every question has exactly one home, decided by the question, not by where a symptom showed** - "what does the source spell" is detection, "what does the transpiler owe" is a decision, "which nodes spell it" is the render canon, "how do nodes land in the host tree" is the binding; a rule answering two of these is split along that ladder.

The core is this package, three layers with one-way dependencies: **detection** (claims, metas, alias and scope facts, the type ladder; parser-dialect questions are answered once by canon predicates - both paren spellings, both optional-chain spellings - no adapter layer exists for detection), **decisions** (inject/collapse/guard/bail, side-effect order, the per-method biases, deopt verdicts - conditioned on source and targets, never on the host), and the **render canon** (the guard ternary, memo, collapse and import shapes), which builds literal ESTree nodes from the closed builder vocabulary.

A **binding** is everything host-shaped in a plugin: parser, traversal with its re-visit semantics, scope queries, host obligations (babel: a foreign tree, scope registration, requeueing; unplugin: print, sourcemaps, id filtering, SFC), the per-leg detection adapter, and the insertion of canonical nodes - unplugin inserts ESTree as is, the babel binding converts the subtree at the insertion boundary (a converter total over the builder vocabulary and defined on nothing else). A binding holds no decisions and no render forms, and it is the only place allowed to know which leg it is - a host branch inside the core is a defect. Parser, traversal and print stay per-leg forever; that IS the product: unplugin is one fast oxc pass with its own print, babel is a citizen of a foreign pipeline whose output tree is read by later plugins. Bytes are dialect, structure is canon.

A name living in BOTH legs is not by itself a duplicate: the binding surface twins by construction - visitor factories, injection and resolver entry points, the per-leg emitters performing a host surgery. What must never twin is the ANSWER inside them: two same-named functions differing only in the surgery around identical plan and render calls are correct as they are; two that re-derive one rule - a wrapper peel, an entry choice, a guard spelling - are one edit, and the rule belongs here. Judge such a pair by what it decides, never by how alike the bodies read.

Divergence taxonomy (closed): (1) formatting-class - the structural comparator owns the definition; (2) environmental - host targets resolution, the require dialect, parser acceptance - registered by the sidecars and nothing else; (3) everything else is a binding defect, and an unclassifiable divergence is a bug by construction. Runtime holds the semantic oracle (native three-way, stripped realm, e2e) - leg parity is blind to a shared root by construction, and the other leg's baseline is never the truth, only the other leg's output.

Classification is by PREDICATE or structure, never by a raw name: a decision read off an identifier holds exactly until the first shadow, alias or slot mutation and is silently wrong after it, so ask the canon predicate (`isPristineProxyGlobal`, `isMutatedGlobalSlot`, `isStaticPlacement` and their kin) rather than compare a string. The same rule forbids a named carve-out inside a structural predicate - `tsModuleIsInstantiated` decides by what the namespace body emits, and a list of global names bolted onto it would answer for the name instead of for the program.

The costs to check every change by: a new rule = one core edit; a new spelling = one render-canon edit; a new dialect fact = one edit (converter or canon predicate); a new host = one binding, zero core edits - a paired edit in two bindings is the symptom of a wrong home. Non-goals: no end-to-end single path, no traversal framework, no merging of the two scope trackers, no byte parity between legs.

This is the rule, not the current state: both plugins still carry render code awaiting collapse into the core, and today's sidecars still include accepted spelling divergences - debt this rule retires. While a render is unshared, the live smell is a fix written in both legs (its root is here); once shared, it inverts - an edit to one leg outside its binding is either a dialect fact (belongs in the binding) or semantics (belongs here). Move by collapsing existing paths, never by adding new ones: a new code path needs a written justification; the default fix deletes code.

The mechanical half of that rule: before writing a function or a branch, search for the existing canonical with `npm run canon` (reference: `scripts/canon/AGENTS.md`) - `find` by the entities the code touches plus the operation on them, in more than one phrasing, plus a grep by the data or node type, then `show` to read a candidate whole. The helper usually exists under a name you would not guess and may solve the task by a different mechanism. Extend or export the near-match, lifting it out if it is nested; never fork a copy, and implementing new means NAMING the checked candidates and why each does not fit. Before handing off, `canon -- delta` must come back clean. The wrapper sets and the peels over them are owned by `helpers/ast-patterns.js`: a site spelling such a set by hand is a fork `delta` cannot see, which is what `canon -- sets` enumerates.

## Injection methods

- `entry-global` - replaces a core-js entry import with the individual `core-js/modules/*` imports its targets need. All the side-effect shapes count, not just the bare `import`: `require`, dynamic `import()`, a minifier-joined `require('core-js/...'), b()` in any slot, and any entry subpath. A BINDING import is never an entry, used or not - `import x from`, `const x = require()`, TypeScript's `import x = require()` alike stay where the author wrote them
- `usage-global` - detects API usage and injects side-effect imports for the polyfills it needs
- `usage-pure` - detects API usage and rewrites it into imports from `@core-js/pure`

The injection bias differs by method, deliberately: `usage-global` injects when a polyfill *might* be needed, because over-injection is harmless; `usage-pure` rewrites only when the receiver type is *certain*, because over-resolving it throws at runtime while under-resolving only degrades to the generic polyfill.

Widening `mode` may never NARROW the injected set. The entry data is monotone along the ladder by construction, so the only way to lose a module is a decision that counts what the CONFIGURED layer yielded - resolving a member at a wider mode then drops the constructor a narrower one injected for the same read. A question whose answer must not move with `mode` is asked at the stable layer instead (`isProposalEntry`); the receiver's own obligation is one of those, decided by the source and that fixed layer rather than by a count.

A CONSTRUCTOR resolves to ONE entry per name per file. Its two spellings - the namespace entry and the bare `*/constructor` under it - name the same runtime value, so the widening an escape or an unnameable mutated member obliges covers every reference to that name in the file, not the position that raised it: a per-position answer mints a second binding for one value, and the ctor-identity guard then tests a value taken from one entry against the other, a comparison that passes only while the two modules happen to export the same object. It costs no module either. Both questions reach the resolver as OPTIONS the emitter binds, and the identical one-line closure in each emitter is that seam rather than a duplicate to collapse: the resolve that asks them carries no path, so the provider cannot reach the program node its own name census is keyed by.

WHICH shapes hand their contents out is ONE set (`CENSUS_CONTAINER_TYPES`), read by every walk that follows a container, and a CLASS is one of them: each of its member slots - static, instance, computed alike - is a value whoever holds the constructor reads back, so an escaping class owes them all, and so does the BASE it extends: a static the base holds answers off the subclass name. A `#private` member is the one exception, unreadable anywhere but the class body and unreachable by reflection. A pairing that indexes fewer shapes than that set - the pattern pairer, which knows the two literals - hands such a source out WHOLE rather than answering nothing, the same superset an unfoldable key already gets.

The symmetry stops at globals. Declining to resolve a receiver *type* is safe, but declining to rewrite a polyfillable *global* is not: what stays behind is a raw `globalThis` or `Symbol`, which is exactly what the target engine may not have.

## The global proxies

`globalThis`, `self` and `window` are ONE object here, and navigation through them collapses on purpose. Three questions about a name, each with one home and no second predicate: does a pure ENTRY EXIST for this hop (`navHasUnresolvableProxyHop` - `self` has one and stays erasable anywhere, `window` has none and is the environment PROBE; never "did this target ask for one"); does the NAME at a run's root read that realm at all (`proxyGlobalRootName`, shadow bail and position discipline built in - `function f(globalThis)` is the user's own object); can THIS BUILD spell that root (`realmRootIsSpellable`). The first also settles a defensive `??` / `||` over a bare proxy name: an entry-backed left operand IS the realm object, so the right side is dead, while a probe name keeps the logical live. Accepted price: a plain hop through `window` answers `undefined` where an engine throws - an answer only a READ can take.

A channel answering "I cannot spell this" is never answering "no spelling exists", and every stand-down here is read against that: taken for the second, a run keeps a native `self` read in exactly the realms the ponyfill answers for. The same mistake is what a climb refusing an effect-bearing root, or a plan refusing a sequence under one, makes on the binding side.

Three questions about a hop, three owners: WHETHER it folds is `foldableRealmHop`'s, WHICH hops stand over a ponyfill is the CALLER's, and WHAT the hop is called is `realmHopKeyName`'s alone - a dotted key, a string literal, a template, a pure zero-arg IIFE and a key BOUND to a constant string all name one slot. A predicate gating a fold on the node's own SHAPE gives one hop two names: `['window']` keeps a slot its dotted twin drops, and the two emitters fold one source two ways. What stays computed is decided by EFFECTS and never by spelling - a key the caller has no slot to replay keeps its hop, and so does a hop standing where the source READS its value.

Over a ponyfill - a backed hop below it, or the leaf a collapse already landed - a hop reads THROUGH it and folds onto it, `?.` and all (`globalThis.window.self` is `_self`). A probe standing TERMINAL in a value the SOURCE reads folds nowhere, and a guard TEST is one of those values: the test spells the run it tests, so an unbacked hop inside it keeps its slot whatever navigates it above (`(w = globalThis.self.window?.Array)?.from(x)` tests `w = _self.window?.Array`) - folded away, the test reads an always-defined ponyfill and answers the branch native short-circuits past. What the hop's NAME says about core-js having an entry for it is a different question from what THIS BUILD spells, and a fold reading the first for the second answers for another build's output.

The landing is the swapping tense of the same rule (`landRunOnDeepestBackedSpan` / `proxyRunLandingPure`), and the run's own ROOT is among the spans it lands on: a backed name spelled BARE is the deepest thing pure can back, and a walk stopping above it gives one source two landings. A hop the landing SWALLOWS is the mirror - a read only the environment can fail, so where a `?.` above OBSERVES the run's absence the probe rides the guard's test and the backed hop its ponyfill, written at the hop or not. The hops ABOVE that landing re-hang inside the ALTERNATE, which lands the ponyfill itself; the reader rule belongs to the SWAPPED landing, and a channel that LOWERS instead of swapping reading it stood its whole arm down. What the landed span spells is not the swap's to drop either: a `?.` the source wrote INSIDE it leaves the in-place swap no spelling, so the run goes to the guard-lowering COLLAPSE (`(w = globalThis.window?.self.Array)?.from(x)` tests `w = null == _globalThis.window ? void 0 : _self.Array`).

What the ROOT spells never gates the run above it: a root nothing can spell keeps its own read raw while the hops over it ride the deepest backed span (`window.self.Array` is `_self.Array`), and only a run with no backed hop at all stays raw whole - a raw `_globalThis.self.window` is the spelling of a build whose `web.self` is excluded, not a defect. The acts the swap would discard with the span - a sequence prefix ahead of the root, the write under the run, an SE-bearing hop key - re-emit ahead of the binding, in the slot the source ran them in (`(c++, globalThis).self` is `(c++, _self)`). A carrier that observes the value (`||`, `&&`, a ternary arm) changes none of this.

WHO owns a STORED run's value has one home (`storedValueConsumedAbove`). A store nothing reads through holds the run's own value, and a reader that never dereferences - a `typeof`, an argument, a null test - proves nothing. A read THROUGH the store (a claim, its guard, an instance dispatch, a destructure, a `delete`) proves the value must be the realm object, so the probe folds there whatever the run carries; the consumer renders first, so that read may already be the minted sequence discarding the store, and both tree states answer alike. WHERE a value reaches such a reader is ONE carrier set (`handsValueOn`) - a sequence tail, a further store, both arms of a branch, both operands of a logical, plus the wrapper layers; a branch TEST carries nothing. A hop reading a KEPT store folds onto the value that store hands on, moving the `?.` it owned one member up while a PLAIN hop erases the one above instead.

A guard is load-bearing only over a READ of a value that can be absent - every rule here is that one sentence, asked of its owning predicate, never of a node type. A rendered guard TEST reads at most the probe hop itself (`null == _globalThis.window`), and only where the source's own `?.` asked for the branch. A CONSUMING position re-emits the read it discards as a THROW probe riding the collapse, keeping the native throw - except the caller-correct FALLBACK SLOTS, which keep the always-defined literal (accepted divergence: the slot fires only when nothing was passed), and a SEALED receiver read in the flat synth-swap, which probes like any seal. A seal is load-bearing only when it hides a SHORT-CIRCUIT (`chainSealsAShortCircuit`); over a plain navigation the nav collapses like its unsealed twin.

The mutation exception (`mutationGuardKeepingHop`) fires where the two canons FORK: a probe read off a span pure lands ALWAYS-DEFINED (`globalThis.self.window` reads the host exactly like `globalThis.window`), which the value canon calls defined for a READ - and there the `?.` the source wrote decides whether the MUTATION lands, so the hop keeps its slot and the guard channel owns the shape. A probe the value canon already calls absent-able earns its guard through the ordinary channels; a base that is itself an unbacked probe, or that carries a hop naming no realm, is absent-able rather than void, so the read through it THROWS and the `?.` above is dead by throw. WHERE the verdict is asked follows what the consumer would DROP: a RENDER weighs the `?.` its own substitution erases and asks at the claim, a FOLD reaches the hops ABOVE the claim and asks of the whole RUN - a seal, a TS wrapper or a further hop parks the deciding marker exactly there.

A `delete` performs no read, so its navigation collapses WHOLE - except a live `?.` whose OWN key is the unresolvable hop, which decides whether the delete HAPPENS and keeps its guard. The base such a fold lands is the run's ROOT binding, and where the build can spell no root either it rides the deepest backed span like every other run, because what the root spells gates nothing above it (`delete window.self.a.b.x` lands `_self`). The claimless call-rooted channel is anchored at the member ENDING the all-proxy run for EVERY consumer, the `delete` fold included: anchoring at the chain TOP hands the plan a run with plain members inside it, which it declines outright, and the `?.` the source wrote over the whole run stands on that end member rather than on any hop inside it.

Marking a proxy global handled says "no second rewrite inside my span", never "my render consumed it"; the two coincide only for a receiver-LESS claim. An instance claim's receiver, a `delete` target and a declined claim are still live reads owing their own substitution - ask that of the RENDER, not of the claim's resolvability. And the transform is not a fixed point over these collapses: a second pass may fold one hop further once the first normalized the root, and an already-lowered input carries no `?.` for the rules to reach - a `pre` and a `pre+post` leg may legally differ there, and neither is wrong.

## Accepted semantic boundaries

Beyond the proxy-realm divergences above, these are design decisions with an accepted price:

- **Plugin output is not typechecked.** The transformed source does not have to pass `tsc`, and does not, for several independent reasons - for one, a synth-swap builds an object literal while the TS assertion stays outside it: `function g({ at } = x as string)` becomes `function g({ at } = { at: _atMaybeString(x) } as string)`, a `TS2352`. Runtime is identical, the `as` erases. Typecheck the source before the plugin, not after it. What a render still owes such an assertion is decided by what it stands on: a RUNTIME narrowing outranks the wider type, so a wrapper the source wrote around a VALUE a render replaces survives it (`(q = globalThis.self as any)` keeps its `as any` over the ponyfill), while one written around a READ the render erases goes with that read (`((eff(), g.self) as any).window` folds to `(eff(), _self)`).
- **`with` and direct `eval` are OPAQUE to the binding census, and modelled there.** A direct `eval` runs its argument in the caller's own scope chain and can assign every binding it reaches - strict mode confines DECLARATIONS, never assignments, so a module is no shelter - and a `with` head answers a body read off its object before the binding does. Both canonical violation builders carry the record, so every positional band ranks it like any other write and the reference walk answers "not enumerable" rather than a subset. An INDIRECT eval reaches no local binding, which is what the callee peel has to keep apart. Outside the model: the same constructs' effect on the VALUE canon, where a name unbound inside a `with` body still reads as the pristine global - the coarse census is a superset on purpose, so the price falls on `usage-pure` alone.
- **`Symbol.iterator in x` is a value test.** `usage-pure` rewrites it to an is-iterable check (`helpers/in-expression.js`). The price: a primitive RHS loses the native `TypeError`, and a present-but-`undefined` `Symbol.iterator` answers `false`.
- **Where the value canon gives up, `usage-pure` keeps its substitution.** A PARAMETER's value comes from the CALL SITE, so a REST parameter's slot, a library CALLBACK's parameter and a transitive hop (`outer(Map)` -> `outer(x) { inner(x) }` -> `inner(y) { y.m = shim }`, `super(t)` included) sit outside it - each wants a flow model, not a wider pairing. A composite VALUE fan branches two ways per level, so past its depth budget the leaf list is cut with no signal - reachable only with the polyfillable name in the DEEPEST arm. The coarse census stays a superset in both (an unnameable root fires the gate), so the price falls on `usage-pure` alone: the read keeps the ponyfill over the value the author installed. Rejected, not to be reopened - deopting the KEY across every constructor that carries it closes the parameter shapes without a flow model, at the price of `opts.assign = f` killing `Object.assign` for a whole file.
- **Partial assignment state on throw.** The pure destructure collapse reorders assignments, so a throwing pattern may leave different siblings assigned than native - observable only via `try/catch`. Source-order fidelity is not promised.

## Caller-correct emission

The polyfill for a destructured parameter belongs in the parameter's own default slot, mirrored to the pattern:

```js
function f({ Array: { from } } = { Array: { from: _Array$from } }) { /* ... */ }
```

Only that slot fires exactly when no argument is passed, leaving a caller's own object to destructure natively. A leaf default (`{ from = _Array$from }`) cannot tell "no argument" from "an argument without that key" - `f({ Array: {} })` would get the polyfill where the source gives `undefined` - and a body extract ignores the caller outright. Those two are allowed only for a local function whose every call provably passes nothing, as decided by the resolver's existing call scan. Otherwise: replace the whole receiver, then extract, then the leaf default; an ambiguous receiver bails.

The USER's default on a destructured leaf follows the read it guards. Over a STATIC the extraction binds the polyfill's own import, never undefined, so the default is dead text and drops on both legs (`{ from: F = fb } = Array` -> `const F = _Array$from`, `renderStaticDefaultGuard({ alwaysDefined })`); over an INSTANCE dispatch, a hop memo or a static read through a nav the value may be undefined and the guard stays (`renderInstanceDefaultGuard`, `_ref === void 0 ? fb : _ref`). A static's ponyfill read by several leaves of one level memoizes once (`memoizedName` in `resolveDestructureReceiverPlan`): the import re-reads for free, but both legs spell one memo.

A nested leaf whose level keeps siblings is the flat twin written the long way (`{ y: { at, other } } = box` reads what `{ at, other } = box.y` reads), and a level ABOVE the leaf that keeps siblings does not stop the twin: the hop leaves that level for a declaration of its own beside the host, which goes on binding its siblings off the root (`resolveNestedReceiverChain({ siblingLevels })`, `hopSplitPlan`, `pruneHopFromLevels`). A built-in root - an unbound name, a resolved base, a nav into the realm - re-reads for free and unobservably, so the split serves any level and any position, with the pair behind the host; a user root re-reads for free only at the host level and its getters keep the source's order, so the hop stands at an end there and the pair goes ahead of the host when the hop led. The pair needs a statement slot of its own: a loop head, a bodyless slot, an export and a declarator that is not the last decline on both legs.

The mutation census pairs a written slot with its container by DECLARATION, not by name: every raw record carries the scope chain it was spelled in, a name resolves to the innermost declaration that chain reaches, and the receiver walk asks about a container through its declaring node - so a namesake in another function never blocks a read. A plain alias of a slot or of a name (`const a = r.w`, `var _r = r`, and the spelling a destructure lowering ahead of the plugin leaves) is no escape: writes and escapes through it canonicalize onto the aliased path at publish time. A wrapper literal holding a container by name (`const box = [r]`) is followed the same way. A second value on the name, a reassignment, a slot written through the container, or a handout to a call still deopts.

A slot default is not an extraction. `{ K: v = _pony }` fires only where the slot reads `undefined`, so wherever core-js REPLACES a present native - the entries whose pure implementation is not the native one, `Promise`, `Map` and `Set` among them - the default binds the native and the polyfill never lands, while an extraction (`const v = _pony`) and a guard (`_ref === Ctor ? _pony : _ref.K`) take the core-js implementation whether or not the slot is defined. So a slot default is allowed exactly where an extraction has nowhere to stand, and its appearance on a NEW shape is a finding, not a choice of render. The head of a for-x is not such a place: what it destructures is an ELEMENT of the iterated literal, and the receiver mirror puts the polyfill straight into that element (`for (const { Map: m } of [{ Map: _Map }])`), where every pass reads it - a minted extraction is owed only where the mirror cannot be spelled: an opaque iterable, an instance claim, a rest neighbour.

## Predicates read through wrappers

The two legs' parsers disagree about what reaches the tree: oxc keeps `ParenthesizedExpression`, babel drops it, and a TS assertion arrives only down the path that parsed as TS. So a predicate here answers differently about the SAME program depending on which leg asked whenever it tests a RAW node's `type`, navigates a fixed number of parents, or compares a peeled side against an unpeeled one. That is a divergence, not a spelling difference, and no fixture sees it - both legs print valid code and only their import sets differ. Peel first: `unwrapRuntimeExpr` for a node, `peelTransparentExprAncestorPath` for a climb, `stepOverChainWrappers` where the answer needs BOTH halves - the reader standing above and the node that reader sees. Never `unwrapExpressionChain` in a predicate weighing EFFECTS - it elides a sequence prefix along with the wrappers.

The dialects disagree about WHERE a node hangs, too, and that moves scope rather than spelling: babel hangs a member's computed key and its decorators off the FUNCTION, estree off the `MethodDefinition` / `Property` above it. A climb trusting the nearest function frame therefore reads a body `var` as covering a slot the language evaluates where the class is DEFINED, on the babel leg alone - so every PATH climb owes the whole frame set (`useRegionFrames`), while the region test over a NATIVE binding owes the parameter-decorator arm alone: both trackers already scope a method's own key out of that method, and widening it there would report a binding declared INSIDE the key as invisible to a use inside it.

One dialect reaches ONE leg: Flow. The babel binding parses it when the file asks for it, oxc has no Flow grammar at all, so every Flow-shaped arm in here - `ObjectTypeProperty` and its kin in the member and awaited resolvers, `DeclareClass` / `DeclareFunction` in the ambient ones - is answered by a single parser. The cross-parser suites cannot hold such a row, so the fixture corpus is where those arms are exercised, on BOTH usage methods - a Flow arm is never a global-only concern, and a wrong narrow there lands in a ponyfill substitution. A new Flow arm therefore owes a fixture, and its ground truth is what the declaration promises, never the TS arm beside it.

Both paren spellings are real on ONE leg too: babel's default parser hides source parens in an `extra.parenthesized` flag, `createParenthesizedExpressions` and every estree parser keep a node, and a user may configure either - so a predicate owes both the same answer, asked through the canon (`sealedLayerBetween`, `chainReadsThroughSeal`, the own-chain walks), including for the node a walk ENDS on, where the flag dialect hangs its parens under a TS wrapper (`(nav)!.X`). What the two spellings may differ in is cosmetic only: redundant printer parens, a vestigial `?.` over an always-defined alternate, a residual dead read in a sequence tail.

## Order, not only presence

An effect the source ran before the pattern bound anything keeps that place. The class is a destructuring receiver spelled behind a sequence (`(eff(), globalThis)`): the extraction an emitter inserts is a WRITE, so leaving the sequence with the residual hands that effect the polyfilled binding instead of the value it had. The prefix lifts to where the source ran it and the residual reads the bare tail, each host reaching that place its own way - a statement, a braced slot, a split, or the first extraction's value in a loop header that hosts no statement at all; what the lift keeps is only what can be observed (`dropDeadSequenceElements`). Order changes neither the import set nor the returned value, so the oracle is a runtime effect LOG against native - the fixture gate locks either order just as happily.

## Output the next tool can lower

The emitted code is not the end of the chain: a downgrade pass runs after it, and a shape that pass lowers wrong is a defect of ours even when the fault is upstream. The known class is a destructuring target binding NOTHING - a trailing husk beside one that binds, or a sole husk against a longer literal - which the standard destructuring transform miscompiles silently, losing a binding or a throw. So a residual this pipeline empties sheds its trailing husks, unless the whole residual is husk and its length is what pairs it positionally; `arrayWrapperResidualTrailingShed` is that canon. Neither the fixture gate nor the differential sees this class - they compare our output, never what the next tool makes of it - so a new residual shape is checked by lowering it and looking for a reference the output bound and the lowering left dangling.

## Layout

- `index.js` - the package entry: the polyfill context and the `resolve` that turns a usage site into a meta from the built-in definitions
- `detect-usage/`, `detect-syntax.js` - what the source uses. `detect-syntax.js` is the syntax table: one named entry set per FORM. A set holds what the DOWNGRADE reads, which is somebody else's runtime - so a claim about it is MEASURED by lowering the form, never reasoned from what the form means, and measured under `@babel/plugin-transform-runtime`, because with helpers inlined the babel leg re-traverses them and covers part of the set by accident. A form whose lowering plugin the workspace does not carry is measured from its HELPER sources, which is what `transform-runtime` imports. A JSX or TS spelling of a form is an extra INPUT to its arm, never an arm of its own. `detect-usage/resolve.js` is the value canon - which global a name, a chain or a binding's value stands for - and a resolver that re-derives what a binding holds is a fork of it, whatever it narrows to; the type layer reads the same answer, and that edge is deliberate. `detect-usage/own-output.js` recognizes the plugins' OWN prior output, any emitter and any config, so a re-transform never claims a spelling a pass deliberately left; pass-2 idempotence on the generated corpus is the property it exists to hold
- `resolve-node-type/`, `resolve-node-type.js` - receiver type resolution. It gates the pure path most visibly, but the global path narrows through it too, so a change here moves both import sets. Every fold over ALTERNATIVES of one value - union arms, the branches of an undecided conditional type, the candidates a guard filters - goes through `foldUnionTypes` and its one arm policy, and a guard adds exactly its own certainty and never more than the annotation says without it. A type guard is a descriptor built in `guard-shapes.js` and nowhere else, its test parsed in the scope of the node that HOSTS it, its built-in operand identified through the binding, and a predicate call resolved to ONE overload the way TS resolves it. A guard whose call may not have RUN is three-valued and holds only in the positive direction. The rule only ever removes injection, so every uncertainty resolves to the wide answer
- `resolver.js`, `injector-base.js` - the shared injection machinery: the injector state both plugins subclass, the flush census over the final tree, pure-import liveness and the canonical slot renumber
- `render.js` - the render canon's node factory (canonical-ESTree builders, the closed vocabulary the babel converter is total over), the injected-import render both bindings insert, and the shapes they share: the short-circuit guard with its two null-test spellings, the ctor-identity narrow, the default guards, the synth key and slot read, the proxy-receiver collapse, the nav-guard test base, the alias-held probe read, the `in`-expression plan. A render carrying a BINDING's own subtree takes it through `hostSlot` - identity where the host dialect is canonical, a wrapper the babel converter passes through unconverted
- `destructure-host-shape.js` - classifies destructure hosts into the parser-agnostic booleans both emitters consume, and plans the minifier-sequence split (`planMinifierSequenceSplit`) - the one host rewrite both bindings apply ahead of detection, each with its own surgery
- `plugin-options/` - option parsing and validation, plus - despite the name - the `usage-global` dispatcher and the module injectors both plugin entry points call. Plugin options are trusted build configuration, not attacker-controlled input, and generated identifiers all flow through `findUniqueName` under plugin-owned prefixes - the source being transformed cannot steer an emitted name
- `helpers/` - the cross-emitter canon that must not be forked: AST patterns, the hop descriptor every alias / callee / wrapper walk carries in and hands back (a walk returning a context bag of its own is a fork of it), class walking, the skip-set subsumption rules, `key in obj` handling, path normalization, the require-source canon, the program's import-binding index every "is this name our import" question reads through, and the disable directives in `source-scan.js`. Those are two halves: the line scan that decides coverage, and the re-anchor that carries every honoured opt-out into the pass's own OUTPUT - a reprint lays the nodes sharing a covered line one per line, so each covered statement, member or property is led by its own `-next-line` directive and the next pass decides the same refusals. A directive suppresses INJECTION over the lines it covers, never OBSERVATION: the mutation census still counts a write on a disabled line, because forgetting it would substitute a later read of that slot over the patch the author installed there
- `helpers/ast-patterns.js` also owns WHEN a read or a write runs relative to its source position, and every positional narrow - the straight-line and preceding-assignment finders, the reaching definition, the guard climbs, the loop back-edge climb - asks those predicates and nothing of its own: a `t.isFunction` standing in for one answers wrong for a field initializer. The write side asks one more, `writeOutrunsUse`, for containers evaluating a header slot ahead of the body slots they also host. ONE pair inside a class is not ranked at all - the class's own decorator list against its heritage, which the spec and every downlevel lowering evaluate in opposite orders, so both sides claim the outrun and the answer widens under either. All of these read a NODE's own facts, which makes them a claim on the bindings: a copy an emitter puts in the tree must carry what they read, and each binding loses a different half - babel's clone drops the source offsets, the ESTree leg's the evaluation-frame stamp, and each restores its own
- `resolve-node-type/structural-key.js` - STRUCTURAL IDENTITY, answered off the AST because every shape this layer never modelled - interface, class, object literal, call signature - collapses into ONE identity-less box. Both readings are CONSERVATIVE by construction and must stay so: a partial member list collapses two different shapes onto one string and fires the TRUE branch of a conditional `tsc` answers FALSE. Key EQUALITY answers TRUE, key INEQUALITY answers nothing. The assignability edges BETWEEN families are DATA (`STRUCTURAL_SUPERTYPES`), decided only where the table carries both names, because the constructor registry holds hierarchies of its own. The resolved-type lane answers the same question through the `identity` slot and nothing else: every arm that can answer TRUE for a PAIR of boxes reaches that slot, and one answering from anything else is a fork of it. The spelling that HIDES is JS object identity - an inferred type is memoized on the declaration it came from, so two instantiations of one generic hand both sides ONE object, and reading a shared object as agreement decides exactly the relation the slot exists to refuse
- `resolve-node-type/pattern-bindings.js` - the DEFAULT-PARAM CALLER CENSUS: whether a parameter default's TYPE describes the parameter at runtime. It keeps no shape list of its own, asking `callPairing` and `positionDisposition` instead. `argsUnknown` splits the two users of that list: a census RECORDING what a call installs owes nothing, one PROVING a slot empty must refuse it. The value being a FUNCTION costs two answers - a MEMBER read off one can always hand an invoker out, and `new` hands the identity to every object it builds, so a construction accounts for its own arguments only while that object is DROPPED where it stands. Accepted loss: a non-constructor METHOD is reached by a KEY rather than a name, and the escape canon next door answers whether a receiver can be REBOUND rather than whether an extra CALLER exists, so closing a method's caller set needs a census of its own
- `helpers/ast-patterns.js` additionally owns the MODULE FORMAT, and the strictness model, Annex-B, the injector's import spelling, the CommonJS wrapper's parameter carve-out and the file boundary the caller census draws all read that ONE answer. `importStyle` is EMISSION configuration and stays out of the language half. The verdict rides on the Program node rather than on `sourceType`, because the babel leg may not write to a tree a foreign pipeline reads after it. The SPELLING follows the ESM the file KEEPS - a binding import, any export and top-level await outlive the pass while a bare side-effect import may not

The feature definitions themselves are not here - they come from `@core-js/compat` (`built-in-definitions`, `known-built-in-return-types`).

## Tests

The edit loop, in order, scoped to what the change touches:

- `npm run test-polyfill-provider` - every suite in `tests/polyfill-provider/`: the resolvers, the detectors, the helpers, the option layer, cross-parser equivalence and the escape-analysis domains
- `npm run test-transpiler-differential` - a generated corpus through native and both emitters, comparing runtime results and import sets. Run it bare, always: evaluations are cached across runs, so a repeat costs what the edit changed, and this package decides usage-global detection and injection too - the `pure` token would skip exactly that leg, and a provider change shifts BOTH emitters, which a single-emitter run cannot see
- `npm run test-e2e-usage-pure` - executes the transformed code, in both emitters' bundles and in realms with the native built-ins stripped, so a polyfill that was never injected fails instead of silently passing on a native

The provider suite alone is not enough, and neither are the plugin fixtures: babel-vs-unplugin parity is blind to a regression that sits here and shifts both emitters the same way, and fixtures happily lock a wrong decision as long as both renderers agree on it - the differential and e2e above are the oracles without that blind spot. Where a rule's whole point is a DIVERGENCE from native - the `delete` collapse, the guard-test base - the differential cannot hold the row at all: those live in `tests/e2e-usage-pure` and in the fixtures. The finish line, once, right before handoff and never mid-loop: `npm run test-transpiling` (a VERY heavy composite of every suite named here plus every plugin runner), then `npm run test-transpiler-perf` - never with a member on the same invocation line.
